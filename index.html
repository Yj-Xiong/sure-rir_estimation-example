04

Reproduce the Harness run

Rec-RIR monaural · 20 fixture rows · pinned SURE and evaluation engine

This runnable backend example scores rir_nmse, rir_corr and rt60_mae. The 60 fixed-SNR rows shown above use a newer NPM protocol and are a separate result set. Run the commands in one working directory and carry the variables into the allocated cluster shell.

Full reproduction notesFixture provenanceSaved report

  1. Get the pinned sources

    Git · local source access

    The pinned SURE and engine commits are currently available from local source checkouts. Set those paths before cloning; the engine gitlink must resolve to 8041b1249c5d.

    git clone https://github.com/Yj-Xiong/sure-rir_estimation-example.git
RIR_EXAMPLE="$PWD/sure-rir_estimation-example/example"
SURE_SOURCE="/absolute/path/to/sure-harness"
ENGINE_SOURCE="$SURE_SOURCE/sure/external/sure-evaluation"
MODEL_SOURCE="/absolute/path/to/Rec-RIR"
git clone --no-checkout "$SURE_SOURCE" sure-rir-repro
git -C sure-rir-repro checkout 73975931da1353c3b97a422e796612d8b363fe3b
git -C sure-rir-repro config submodule.sure/external/sure-evaluation.url "$ENGINE_SOURCE"
git -C sure-rir-repro -c protocol.file.allow=always submodule update --init sure/external/sure-evaluation
git clone --no-checkout "$MODEL_SOURCE" rec-rir-source
git -C rec-rir-source checkout 6914eea792f0117e39f87510ffbda7cd04dffbbb

  2. Prepare the locked runtimes

    Run model environment setup on the cluster

    The checkpoint is part of the pinned Rec-RIR source. Its SHA-256 must be afe36e477f6fb3656d162d906a47da2d40a789634b476564266fc1ba36037478. A fresh Mamba install may compile CUDA extensions.

    SURE_REPO="$PWD/sure-rir-repro"
MODEL_REPO="$PWD/rec-rir-source"
MODEL_CHECKPOINT="$MODEL_REPO/ckpt/epoch35.tar"
HARNESS_PYTHON_BIN=$(python3 "$SURE_REPO/sure/runtime/harness/bootstrap.py")
sha256sum "$MODEL_CHECKPOINT"
uv venv --python 3.10 .venv-rir-model
MODEL_PYTHON="$PWD/.venv-rir-model/bin/python"
uv pip install --python "$MODEL_PYTHON" \
  'torch==2.2.0' 'torchaudio==2.2.0' 'mamba-ssm==2.1.0' \
  'causal-conv1d==1.4.0' 'numpy==1.26.4' 'soundfile==0.13.1' \
  'toml==0.10.2' 'tqdm==4.68.2' 'jsonargparse==4.48.0' 'matplotlib==3.10.8'

  3. Check the adapter and fixture

    Short check · no model inference

    This checks all 20 fixture rows, the published report identity and the MCP initialize/tools/list/shutdown replies. Expected result: four tests pass.

    "$MODEL_PYTHON" "$RIR_EXAMPLE/test_example.py"

  4. Run inference and evaluation

    Cluster job · GPU

    Run inside a cluster allocation with a new output directory. The model only sees channel-0 audio; reference RIRs enter the Harness scoring bridge. This step generates 20 new RIR WAVs and three external metric reports.

    "$HARNESS_PYTHON_BIN" "$RIR_EXAMPLE/run_example.py" \
  --repo "$SURE_REPO" \
  --model-repo "$MODEL_REPO" \
  --checkpoint "$MODEL_CHECKPOINT" \
  --model-python "$MODEL_PYTHON" \
  --device cuda:0 \
  --output-dir "$PWD/rir-run-001"

  5. Verify the new report

    20 samples · matching pipeline identity

    The runner checks that Harness and the pinned engine agree on all three scores, every metric has 20 rows, and describe/run/report preserve pipeline and node identities. Inspect the generated summary and report:

    "$HARNESS_PYTHON_BIN" -m json.tool "$PWD/rir-run-001/summary.json"
"$HARNESS_PYTHON_BIN" -m json.tool "$PWD/rir-run-001/evaluation/report.json"

  6. Compare the saved evidence

    Previously completed · 20 real predictions

    The completed run records Rec-RIR checkpoint, Runtime IDs, model environment, metric results and pipeline description. Raw prediction WAVs remain outside this public repository. Compare against the saved summary and pipeline description; numerical results can differ after changing hardware or dependencies.
